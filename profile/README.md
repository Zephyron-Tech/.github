## What we build

Companies come to us when they have outgrown spreadsheets but don't need a million-crown ERP. We design the system, write it, deploy it on infrastructure we run ourselves, and keep it going after launch.

- **Internal systems.** Order tracking, capacity planning, inventory, client portals. Built around how a team actually works, delivered in stages so the first part is in use within weeks.
- **Process automation.** Integrations between accounting, CRM, e-shops and bank statements over their APIs. Documents, reports and reminders generated from data that already exists.
- **Web applications.** From marketing sites to full-stack apps with auth, admin and integrations.
- **Infrastructure and operations.** Servers, DNS, backups with tested restores, monitoring. We usually know about an outage before the client does.
- **Startup Support.** A long-term technical partner for founders without an engineering team, from the first architecture sketch to production.

## Whitecoding

Our name for how we work. Code a new developer can read on day one, infrastructure we can explain end to end, and no part of the stack we can't replace.

- **Self-managed infrastructure.** We run our own servers with Docker and Traefik. Deployments, logs, backups and databases stay under our control and the client's, not a vendor's pricing page.
- **Modular, not monolithic.** Small services with clear boundaries instead of a heavy CMS that dictates the data model. Each part can be rewritten without touching the rest.
- **No lock-in.** Open standards and portable containers. If a client moves on, their system moves with them.
- **Performance as a requirement.** Server-rendered pages, typed APIs, indexes planned with the schema. Fast is part of the spec, not a later ticket.
- **Boring where it counts.** PostgreSQL before something trendy. New tools only when they solve a problem we actually have.
